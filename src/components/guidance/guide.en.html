This app simulates operator workload on the production floor: how many machines one operator can handle, their man occupation, and the output of one shift.

Overview & roles

There are two simulators. The Work Load Simulator models one operator handling a set of machines that all run one Construction Detail. Production Simulation models many operators and many Constructions at once on a plant layout.

Work Load Simulator

The flow has two stages: 1. Setup then 2. Simulation. Setup has two steps: Setup and Machine Layout.

Step 1 — Setup

  1. Pick a Construction Detail at the top (filter by Area, Mach, Product). The app fills Machine Specification from WL_Products and the Activity Table from WL_Activities. Operator settings (Task Priority, shift, lunch, meeting, RPC, Walking Speed, Doff Priority) come from Setting → Default Values.
  2. Machine Specification: LayLength, NoOfWires, Speed, SpoolLength, LinearDensity, Fracture/Dies/Defect per ton, POlength. Spool Weight and Runtime/spool are derived from these.
  3. Operator Activities: Task Priority, Shift Time, Lunch/Meeting (duration and start minute), extra breaks (+ Add activity), Available Time with Walking Speed (m/min) beside it, and at the bottom Doff Priority and Min Remain Task for Doff Priority.
  4. Output Estimate: estimated output and man occupation before running. Set # Assigned Machines, or click Optimize Man Occupation to find the most machines the operator can keep up with (Forecast Man Occupation up to 100%, no backlog). Machines still wait even below 100% man occupation, whenever several need the operator at once (machine interference); the dropdown before Optimize (Admin only; everyone else follows Setting → Default Values) picks how that's estimated: Wright's formula, the Finite source queue (M/M/1//N), or None (no interference: machines only wait for the backlog). Changing it re-runs Optimize, and Save WLM stores it (OptimizeModel). Waiting for Operator is the larger of that interference and the backlog. It lowers OEE, and spools per machine (Shift × OEE ÷ runtime) and so the operator's work follow from that OEE, solved together because less production also means less work and less waiting. The fx button next to Forecast Man Occupation shows the calculation step by step: available time, machine availability, every activity's demand, walking, the interference and machine downtime.
  5. Activity Table: Time, Frequency Type, Numerator, Denominator and Mach Condition per activity. RPC % sits right of the table title. Add sub-activities with + Sub Doffing or + Sub Loading.

The circular-arrow button resets every field to how it was when the Construction Detail was picked.

Step 2 — Machine Layout

  1. Pick a saved layout from Layout Builder, or build one on the canvas.
  2. Select machines and Assign. The number assigned must equal # Assigned Machines.
  3. Optional: set an operator start point. Without one, the operator starts at the first machine.
  4. Click Validate & Start Simulation.

Simulation stage

  • ▶ Play, ⏸ Pause, speed buttons and Reset. # Mach Assigned and Fracture per Ton can only be changed after a Reset.
  • The Operator Timeline and Machine Timeline show what happened each minute. Click an operator segment to highlight the related machines; click a machine row for that machine's summary.
  • Dashboard: Output (Running Time), Output, Man Occupation, OEE & Downtime, Completed Activities, Activity Log. Each value is followed by / ~ and the setup's forecast for the full shift (the Output Estimate), so actual and forecast can be compared. Drag the panel's left edge to make it wider or narrower.
  • Save WLM saves the result to WL_Outputmodels. If that Construction Detail already has a saved result, you'll see a comparison with the old version and can replace it or save a new version (a Version remark is required for a new version).
  • After the shift ends: view the output details, or Copy output (tab-separated, pastes into Excel).

Layout Builder

Where you build machine layouts to reuse in both simulators.

  • Add Group Machine: create a block of machines by rows, columns, orientation (Vertical: PO top, TU bottom; Horizontal: PO left, TU right), Pair/Single, and machine size in meters.
  • Select machines to copy/paste (Ctrl+C / Ctrl+V, including repeated paste left/right), flip orientation, toggle type BF/X, resize, or renumber.
  • Walls: operators must walk around them. Remarks: text notes that don't block walking.
  • Measure distance to measure, and the operator start point for where operators begin.

Production Simulation

Creating a Production Setup

  1. Pick a Layout, type a setup name, click + New Setup. The layout is copied into the setup (later layout edits don't carry over). Shift and movement values start from Setting → Default Values.
  2. Fill Shift & Movement Settings: Task Priority, Shift/Lunch/Meeting, RPC %, Doff Priority, Min Remain Task, Waiting Model (Admin only — everyone else follows Setting → Default Values; how the man occupation forecast estimates machines waiting for an operator; the ⓘ button explains each), Walking Speed.
  3. Add operators in the Operators card: one at a time, or in bulk with a prefix and count (e.g. Opr_0001). The number next to each name is that operator's forecast man occupation.

Assign Selection

Select machines on the canvas (click or drag), then work down the panel. Each field has an Apply button and a remove button. An Apply button turns yellow when its field has changes not yet applied.

  1. Construction Detail of the machines.
  2. Group Name: a free-text label for reporting machines together.
  3. Assign Type tabs: only pick which operator fields show; it isn't saved.
    • Multi Task → add one or more operators. Any of them may do any task on those machines.
    • Split Task → add one or more operators per activity: Doff, Load, Fract, Dies, Defect. They only do that activity.
  4. Doff Priority (optional): a toggle and Min Remain Task for the selected machines only. The remove button sets them back to follow the setup.

A machine can have Multi Task and Split Task operators at once. Switching Assign Type keeps the other type's operators; a hint below lists them. An operator is one or the other on a machine: someone already Multi Task on the selection isn't offered in Split Task, and the other way round. A machine with no operator yet opens as Multi Task.

Each operator box shows the selection's man occupation if one operator handled that work: the Multi Task box for all tasks, each Split Task box for its activity, with the ideal demand next to it. The selection box on the canvas lists All Task and every activity.

Operators card

  • ⚙️: a per-operator Lunch/Meeting start minute. Blank = follow the setup. Durations always follow the setup.
  • 📊: fullscreen Planned Man Occupation, including demand with no operator yet.

Canvas & Machine Assignments

  • Construction Detail View colors machines by Construction. Operator View splits each machine body by operator. Hover a legend entry to highlight its machines; the legend has Construction, Operator and Machine Group tabs.
  • The Machine Assignments table lists every column per machine: Construction, Group Name, Multi Task, the operators per activity (hover a count to see the names), and the machine's Doff Priority ("—" = follows the setup). The row above the headers totals each column (machines, distinct Constructions, groups and operators). Group by Construction, Group Name or Operator rolls the table up: per group, how many machines, Constructions, groups and operators (in total, Multi Task and per activity) it has. Under Operator, a machine counts toward every operator working it. Click any column header to sort; click again to reverse. Search keeps only machines with that text in any column (machine, Construction, Group Name, any operator, Doff Priority); totals and Group by then cover just those.
  • Use Export CSV, edit in Excel, then Import CSV. The Multi Task and activity columns take operator names separated by ;. Doff Priority takes Yes, No or blank; Min Remain Task takes minutes or blank (blank = follow the setup).

Running the simulation

Click ▶ Run Simulation. The result page has operator and machine timelines (click an operator's name to filter the Man Occupation card), the Operator List, Output (split into Finish Product and Semi Finish Product by SpoolType BS…), Reject % for OEE Quality, a Downtime Pareto, and the Production Report button. The Production Report can group results by any WL_Products column or by Machine Group (the machines' Group Name).

Simulation rules

Task Priority

Nearest Task: the operator goes to the queued machine with the shortest walk. Quickest Task: the operator picks the machine whose work would be finished soonest (walk plus all work time).

Mach Condition: Run and Stop

  • A Stop activity stops the machine while it's done; the machine is also stopped while waiting for the operator.
  • A Run activity is done while the machine keeps running.
  • A Run activity directly followed by a Stop activity stops the machine too. This also applies when the following Stop activity belongs to another operator and is still waiting on that machine.

RPC (Rest & Personal Care)

Every activity gets extra time equal to RPC % of its time. For example, 12% RPC turns a 10-minute activity into 10 + 1.2 minutes. RPC time shows as its own segment in the timelines (legend "RPC") and as Others (RPC) in Man Occupation. RPC behaves like a Run activity: it only keeps the machine stopped when the next activity is Stop, and that time then counts as downtime of its parent activity.

Doffing, Loading and sub-activities

  • Loading follows POlength in WL_Products when it's filled. Areas WW, BA, CA, IS, IP use weight-based Loading done at the Pay Off.
  • When Loading Partial1 and Partial2 come due together, one Loading Partial3 replaces both.
  • When a machine's Doffing and Loading belong to different operators, Loading waits until Doffing is done; that gap counts as waiting.

Fracture Repairing, Dies Change, Defect Repairing

These are counted per Construction, not per machine: once the combined spools of the machines on one Construction reach the cycle, the event lands on a random running machine. Dies Change applies to Areas WW, BA, CA, with 7 or 26 dies per event. Defect Repairing applies to Areas CB, BU, SP, CH, CR and is done at the Take Up.

Frequency Type (Doffing sub-tasks)

Frequency TypeDone on…
(blank)Num/Dem as usual
FirstDoffAfterLoadingThe first Doffing after a Loading (main or partial)
FirstDoffAfterLoadingAllThe first Doffing after a main Loading
FirstDoffAfterLoadingPartialThe first Doffing after a partial Loading
FirstDoffAfterFractureRepairingThe first Doffing after a Fracture Repairing
FirstDoffAfterDefectRepairingThe first Doffing after a Defect Repairing
FirstDoffAfterDiesChangeThe first Doffing after a Dies Change
FirstDoffAfterInteruptionsThe first Doffing after any of the events above
FirstDoffOnShiftThe machine's first Doffing of the shift

An event counts when it's finished, on the same machine. Several events before one Doffing still give the sub-task once.

Multi Task vs Split Task

A task on a machine may be done by the machine's Multi Task operators and by that activity's Split Task operators, whoever is free first (by Task Priority). Only one operator works a machine at a time. Sub-tasks (e.g. ScanMES, Loading Partial) follow their parent activity. Loading waits until the Doffing is done when the operator can't do the Doffing too. Dies Change and Defect Repairing use their own operators; with none set they fall back to the Fracture Repairing operators. In the forecast, an activity's workload is split evenly across everyone who may do it.

Breaks (Lunch, Meeting, Other)

When a break is due, the operator first finishes the visit they're on, then takes the full break. Machines that need work wait during the break. In Production Simulation, start minutes can differ per operator (the ⚙️ button).

Doff Priority

When Yes: if the operator is working a machine and another machine needs Doffing while at least Min Remain Task minutes of the visit are left, that work is paused. The operator does all waiting Doffings (by Task Priority), then picks again by Task Priority. Paused work is judged by its remaining time and resumes where it stopped. Doffing work itself is never paused.

In Production Simulation each machine can have its own Doff Priority and Min Remain Task (in Assign Selection). The setting of the machine that needs Doffing is used; when it's blank, the setup's applies. A machine with Doff Priority No never interrupts other work and isn't put first.

Doff Priority cuts Doffing waiting time but adds operator walking. Raise Min Remain Task if pauses happen too often.

Glossary

Construction
The product construction code; its text holds Mach-Product-LayLength-TG-SpoolType.
Construction Detail
One WL_Products row; the basis for the machine spec and Activity Table.
Area
Production area (BU, CB, SP, CH, CR, WW, IS, IP, CA, BA); decides the Loading, Dies Change and Defect Repairing rules.
Spool
One reel a machine produces. Spool Weight = SpoolLength × LinearDensity × NoOfWires ÷ 1000 (kg).
Runtime/spool
Time a machine takes to produce one spool.
Doffing
Taking a finished spool off the machine, at the Take Up.
Loading
Replacing/feeding raw material; Loading Partial is a partial load.
Fracture Repairing
Repairing a broken wire.
Dies Change
Changing dies.
Defect Repairing
Repairing a product defect.
Pay Off / Cradle / Take Up
Work zones on a machine where the operator stands (PO, cradle, TU).
Mach Condition
Stop (machine stops) or Run (machine keeps running) while the activity is done.
Num / Dem
Numerator / Denominator: the activity happens Num times every Dem spools.
Frequency Type
An event-based frequency rule for Doffing sub-tasks.
RPC
Rest & Personal Care: an extra % of time for rest and personal needs.
Task Priority
How the operator picks the next machine: Nearest or Quickest.
Available Time
Shift Time minus Lunch, Meeting and other breaks.
Man Occupation
(Walking + Handling) ÷ net working time, in %.
Ideal demand / Forecast
Theoretical workload vs the estimate after machine stops and walking.
Others (RPC)
The RPC share of time in Man Occupation.
Idle
The operator has nothing to do.
Downtime / Waiting
The machine is stopped: for a Stop activity, or waiting for an operator.
OEE Availability
(Planned production time − downtime) ÷ planned production time.
Reject % / Quality
Share of reject tonnage; reduces good tonnage and OEE (Production Simulation).
Manhour/ton, Machhours/ton
Operator hours or machine hours per ton of output.
Multi Task / Split Task
Operators who may do every task on a machine / only one activity on it.
Group Name
A free-text label for reporting machines together.
Doff Priority / Min Remain Task
Pausing work for Doffing when at least Min Remain Task minutes of the visit are left. Set per setup, and in Production Simulation per machine too.
WLM / Output model
A simulation result saved in WL_Outputmodels, with versions.
Inherited condition
Starting machine conditions + seed from a saved result, to replay a simulation.
